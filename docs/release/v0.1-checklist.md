# AgentGuard v0.1.0 Release Checklist

This is the release-readiness checklist for AgentGuard v0.1.0. It maps the
release-level Definition of Done to evidence that must be collected before a
release-readiness decision is made.

The checkboxes are intentionally unchecked when this checklist is created.
Creating this document does not assert that any release-level item is
complete, and it does not authorize a tag, GitHub Release, npm publish, or
other remote write.

## Release-level Definition of Done

### Platform and CI

- [ ] Windows CI passes on the supported Node 24 runtime.
- [ ] Linux CI passes on the supported Node 24 runtime.
- [ ] macOS CI passes on the supported Node 24 runtime.
- [ ] The CI evidence identifies the exact Node and package-manager versions.
- [ ] No release claim relies on the local Node 25 host, which is outside the
      repository engine range.

### Core product behavior

- [ ] Node project detection is validated with positive and negative evidence.
- [ ] Git diff analysis is validated for the supported base/head inputs.
- [ ] Test, typecheck, and lint verification are validated with their distinct
      statuses and evidence.
- [ ] Optional build verification is validated according to the configured
      project/build intent.
- [ ] All five built-in rules have deterministic positive and negative cases,
      evidence, severity, registry inclusion, and documentation.
- [ ] The normative v0.1 Risk Model is validated, including severity weights,
      verifier penalties, score capping, thresholds, and verdict boundaries.
- [ ] Finding confidence is confirmed not to affect v0.1 Risk Score.
- [ ] `VerificationResult.status = "error"` remains distinct from an
      AgentGuard internal error and internal errors retain exit code 3.
- [ ] Evidence output is validated in every supported report format.
- [ ] CLI behavior is validated, including help, version, applicable commands,
      verdict exit codes, and the internal-error path.
- [ ] GitHub Action inputs, outputs, failure behavior, and bundled artifact are
      validated without claiming unobserved live GitHub execution.

### Documentation and examples

- [ ] English README is complete and matches the implemented v0.1 surface.
- [ ] Chinese README is complete and matches the implemented v0.1 surface.
- [ ] Architecture and trust-boundary documentation matches the source.
- [ ] Configuration, evidence, rule, report, exit-code, and Risk Model docs
      are consistent with the normative specifications.
- [ ] The basic example is reproducible from a clean checkout.
- [ ] The bad-AI-PR example is reproducible and demonstrates the intended
      findings/evidence/verdict behavior.
- [ ] Release notes are prepared from validated behavior only.

### Security and release hygiene

- [ ] No known critical security issue remains open for v0.1.0.
- [ ] No untrusted shell string is executed by the implementation or examples.
- [ ] JSON configuration remains data, not executable code.
- [ ] Core/domain code remains free of Node runtime imports and `console.log`.
- [ ] No LLM, network-based scoring, confidence scaling, category scaling,
      undocumented multiplier, or other non-normative Risk Score behavior was
      introduced.
- [ ] Repository identity, package metadata, and release workflow are reviewed
      against `Felyx-Fu/AgentGuard` without performing remote writes.

## Public package artifact gate

The following seven packages are the v0.1 public npm package set:

- `@agentguard/contracts`
- `@agentguard/core`
- `@agentguard/runtime-node`
- `@agentguard/rules`
- `@agentguard/config`
- `@agentguard/report`
- `@agentguard/cli`

- [ ] Each public package has a package-local `tsconfig.build.json` using
      unbundled TypeScript output under `dist`.
- [ ] `pnpm build` produces JavaScript, declarations, declaration maps, and
      source maps for every public package.
- [ ] Each packed manifest has the canonical repository metadata and accurate
      `repository.directory`.
- [ ] Each packed manifest is ESM-only and maps the package root to
      `./dist/index.js` and `./dist/index.d.ts`.
- [ ] The packed CLI bin maps `agentguard` to `./dist/main.js`.
- [ ] Each tarball contains only package metadata, package README, MIT LICENSE,
      and `dist/**`.
- [ ] Source, tests, fixtures, coverage, development TypeScript configs,
      temporary files, and unrelated tooling are absent from every tarball.
- [ ] Packed internal dependency ranges contain no unresolved `workspace:`
      specifier.
- [ ] A clean external npm consumer installs the packed artifacts.
- [ ] The external consumer resolves representative ESM package-root imports.
- [ ] The external consumer resolves TypeScript declarations in strict mode.
- [ ] The external consumer runs `agentguard --help` from the packed CLI.
- [ ] The private GitHub Action is checked separately and is not treated as a
      public npm package.

## Evidence record

For every checked item, record the command or review source, the date, the
runtime/tool versions, and the exact result in `STATUS.md` or the applicable
release evidence file. A failed, skipped, or unavailable check must remain
visible and must not be converted into a release claim.

## Stop conditions

Pause release-readiness work and record `BLOCKED` if a required check exposes a
real architecture, security, specification, packaging, or cross-platform
correctness blocker. Do not weaken a gate, broaden scope, or perform a remote
write to bypass a stop condition.
