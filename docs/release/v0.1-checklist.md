## Release-level Definition of Done

### Platform and CI

- [x] Windows CI passes on the supported Node 24 runtime.
- [x] Linux CI passes on the supported Node 24 runtime.
- [x] macOS CI passes on the supported Node 24 runtime.
- [x] The CI evidence identifies the exact Node and package-manager versions.
- [x] No release claim relies on the local Node 25 host, which is outside the
      repository engine range.

### Core product behavior

- [x] Node project detection is validated with positive and negative evidence.
- [x] Git diff analysis is validated for the supported base/head inputs.
- [x] Test, typecheck, and lint verification are validated with their distinct
      statuses and evidence.
- [x] Optional build verification is validated according to the configured
      project/build intent.
- [x] All five built-in rules have deterministic positive and negative cases,
      evidence, severity, registry inclusion, and documentation.
- [x] The normative v0.1 Risk Model is validated, including severity weights,
      verifier penalties, score capping, thresholds, and verdict boundaries.
- [x] Finding confidence is confirmed not to affect v0.1 Risk Score.
- [x] `VerificationResult.status = "error"` remains distinct from an
      DiffSentry internal error and internal errors retain exit code 3.
- [x] Evidence output is validated in every supported report format.
- [x] Top-level CLI behavior is fully validated, including the required
      `diffsentry check` executable flow; the existing command API, help/version
      path, verdict mapping, usage errors, and internal-error mapping are
      covered by tests and the real built executable E2E.
- [x] GitHub Action inputs, outputs, failure behavior, and bundled artifact are
      validated without claiming unobserved live GitHub execution.

### Documentation and examples

- [x] English README is complete and matches the implemented v0.1 surface.
- [x] Chinese README is complete and matches the implemented v0.1 surface.
- [x] Architecture and trust-boundary documentation matches the source.
- [x] Configuration, evidence, rule, report, exit-code, and Risk Model docs
      are consistent with the normative specifications.
- [x] The basic example is reproducible from a clean checkout.
- [x] The bad-AI-PR example is reproducible and demonstrates the intended
      findings/evidence/verdict behavior.
- [x] Release notes are prepared from validated behavior only.

### Security and release hygiene

- [x] No known critical security issue remains open for v0.1.0.
- [x] No untrusted shell string is executed by the implementation or examples.
- [x] JSON configuration remains data, not executable code.
- [x] Core/domain code remains free of Node runtime imports and `console.log`.
- [x] No LLM, network-based scoring, confidence scaling, category scaling,
      undocumented multiplier, or other non-normative Risk Score behavior was
      introduced.
- [x] Repository identity, package metadata, and release workflow are reviewed
      against `Felyx-Fu/DiffSentry` without performing remote writes.
